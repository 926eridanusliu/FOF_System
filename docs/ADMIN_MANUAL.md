# 管理员运行手册

## 每日检查

- `GET /health` 返回 `status=ok`。
- 磁盘空间足够保存数据库、上传图片、版本快照和生成报告。
- 最近生成任务没有长期停留在 `queued/running`。
- 飞书通知没有持续 `failed`。
- 备份任务最近一次成功，并且备份文件可读。

## 安全边界

- `.env`、数据库、上传资料、生成报告、历史版本和飞书私密 JSON 不进入 Git。
- Nginx 对用户提供统一入口；Uvicorn 仅监听 `127.0.0.1`。
- 访问权限、TLS、服务器账号和日志保留按公司内网规范配置。
- `/docs` 是否在生产开放由负责人决定；若不开放，从 Nginx 配置删除对应位置。

## 故障定位

1. 先检查 Nginx 和后端进程是否运行。
2. 本机请求 `http://127.0.0.1:8000/health`，再请求外部入口 `/health`。
3. 查询报告生成任务的 `status/error`。
4. 查询报告通知列表的 `status/last_error/response_status`。
5. `GET /api/notifications/config` 仅显示配置完整度，不泄露密钥。
6. 修复飞书配置或网络后调用通知重试接口。

不要通过聊天或工单粘贴完整 Token；只报告配置项名称和错误摘要。
